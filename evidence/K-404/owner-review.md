- Inputs: the portable K-403 MCP wheel and 31 Linux x64 dependency wheels are byte checked against the hash lock. uv managed CPython 3.13.15 was installed in Debian 12 x86_64 Docker from the uv 0.12.9 Linux wheel, then repacked as a regular file archive. `runtime-input.json` records each candidate SHA and source revision. No network is used by the per-user provisioner.
- Positive: from an isolated home and sanitized PATH, the provisioner created an owned `mcp-runtime/versions/<generation>` Python 3.13 environment. The installed MCP entrypoint reported the expected version/source; `axiom_mcp`, `mcp`, and `fastapi` imported; `pip check` was clean. A repeated request returned `already_current` and kept the pointer bytes.
- Refusals: a changed runtime archive and MCP wheel were rejected before pointer mutation. A Python 3.12 interpreter, missing `mcp` dependency, and interruption before activation were rejected. A tampered retained launcher prevented rollback until restored. A valid rollback restored the previous generation; removal deleted two owned generations and preserved a user sentinel.
- Engine boundary: `src/lifecycle.rs` now reads the verified runtime pointer for both `macos-x64` and `linux-x64`. The owner unit test verifies active Python/launcher hashes before its absolute `venv/bin` is passed to the engine. K-405 will test the full Linux distribution install and service/foreground flow.
- Compatibility/rollback: this candidate was exercised in Debian 12 Linux x86_64 Docker. It is unsigned, unpublished, and not native WSL2 or Windows proof. Removing this feature branch restores the prior Linux behavior; no user installation was modified during tests.
